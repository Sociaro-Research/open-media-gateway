# Media generation product scope

Open Media Gateway generates and transforms **video, images and audio files**.
Speech and music are audio categories. Video regeneration/upscaling, image editing,
lip-sync, soundtracks, mixing and actual media previews remain media workflows.
This boundary applies to every provider, manual connection, discovery result,
API request, Template and browser selection.

Standalone text/context generation, recognition/JSON analysis, resource CRUD and
session/selection state mutations are outside the product's public executable
catalog. A vendor endpoint, an ancillary image or a misleading `video` label is
not sufficient to make a state-management operation a media model. Conversely,
JSON/text/binary sidecars do not disqualify a real generated media output.

## Preparation is part of a media workflow

Reference uploads, owned generated-output bindings, inspected file handling,
voice/element preparation, face detection and editing selections may be necessary
inputs to media generation. Keep these internal adapters and their ownership,
connection-revision, expiry, inspection, pricing, budget and idempotency checks.
They are not independently selectable models or general utility APIs.

Input-preparation metadata is requested for a specific currently authorized media
model. Creation and state mutation require `workflow_model`, resolved on the same
provider connection. Only a native preparation whose output kind/subtype is an
input of that media consumer is eligible. An ordinary generation request cannot
create this internal authorization context. Quotes and submission share the same
checks. Missing/hidden/removed consumers, unrelated helpers and incompatible
subtypes fail closed; renaming or relabelling a saved manual model cannot grant a
new capability. Context-IR text preparation has no reviewed consuming media step
and is not enabled by supplying a video model as a wrapper.

The browser exposes input preparation inside the selected media workflow. It
requires an explicit estimate/review and confirmation before any chargeable
operation. Unknown fees remain unavailable. Closing, changing keys or interrupting
an operation must not cause an automatic mutation retry. Media generation remains
a separate explicit action.

## Compatibility and preservation

Do not delete existing resources, generations, credentials, schemas or history.
Do not change applied migrations. Preserve polling and recovery of already-admitted
jobs, historical metadata, immutable snapshots, authenticated stored media and
ancillary artifact parsing. A model retired from new public admission can still
need its private serializer/parser for recovery. Existing reusable bindings remain
consumable by authorized media workflows.

Discovery advertises reviewed media identities only. Unknown upstream identities
and previously saved model-access records are not authorization to execute. Manual
models must use a supported media request profile at save time and when loading a
persisted connection. All providers are subject to the same server-side boundary;
hiding a Content Type label is not enforcement.

For changes, test catalog/discovery and direct generation/estimate routes, aliases,
stale enabled records/manual descriptors, Template admission/replay, required
preparation chains and historical job/media access. Follow the shared
[design review gate](design-system.md#spacing-and-visual-review-gate) for browser
changes, including both themes, responsive layouts and keyboard behavior.
