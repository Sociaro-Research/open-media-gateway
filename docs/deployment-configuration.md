# Private deployment configuration

The public source contains no operator installation endpoints, SSH/WireGuard
pins or personal key paths. Local checks do not require deployment configuration.
Deployment has no discovery fallback: missing or invalid profile, route, key path
or independently verified Ed25519 identity stops before SSH or tunnel setup.

Use `tools/release/deployment.example.json` and `deployment.schema.json` as the
format reference. The example deliberately has `"example": true` and cannot be
used to deploy. Create and review your own version 1 profile, remove that marker,
and keep its permissions at 0600. The installed launcher reads
`~/Documents/Release Tool/deployment.json`; source commands read the ignored
`.local/deployment.json`. `DEPLOY_CONFIG` selects an explicit alternative file.
Relative pin/key paths resolve beside that profile, never against the checkout.

Keep public trust files in a private `deployment-private/` directory beside the
profile. `known_hosts_file` must include the configured `ssh_host_key_alias`
with its independently verified Ed25519 pin. Preserve established identities
when migrating; never substitute a learned key, disable strict checking or
use `ssh-keyscan` output as verification. `admin_ssh_host` and
`tunnel_ssh_host` identify the administrative and restricted transports.
The latter may use a narrow private WireGuard address while retaining the same
verified host-key alias. Keep the three key roles separate.

`admin_ssh_key_file`, optional `github_ssh_key_file`, and optional
`restricted_ssh_key_file` name existing private files. The loader only checks
private key paths; it never prints or copies their contents. The manual Actions
client may instead consume its dedicated `DEPLOY_SSH_KEY` environment secret.
`repository_url` is the expected origin guard, not an instruction to change Git
configuration. The installed tool's command-scoped GitHub SSH transport retains
strict GitHub host checking and does not rewrite persistent Git settings.

For a tunnel, explicitly configure the endpoint, server public-key file,
client/server `/32` addresses, server-only allowed route and listen port.
The loader rejects a default route or a route broader than the single server.
The client private key may come from its dedicated environment secret or
`wireguard_client_private_key_file`. A missing optional role fails when requested;
no new key is generated by loading a profile. The separate server network
installer provisions only when an administrator deliberately runs it.

`public_origin` is an HTTPS origin without credentials, path, query or fragment.
Server-side smoke checks read the deployed service's actual `AUTH_PUBLIC_URL`
(or Google callback origin) and require the configured UI to share that origin.
They do not inherit an old maintainer endpoint from the source tree.

Installation updates source and example/schema only. It preserves the private
profile, trust files, existing keys and logs. Review the configuration before a
future installation update; creating a profile does not reinstall the launcher,
contact a server or authorize deployment. Never put profiles, trust bindings,
private keys, `.env`, reports or caches into Git, transfer snapshots or Library.
